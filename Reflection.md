# Reflection

The hardest part of this project was turning a simple shopping comparison idea into something that felt trustworthy and useful. A price comparison app is easy to imagine, but the difficult part was deciding what should make one listing safer than another. I had to think beyond price and include seller reputation, product match, warranty risk, fake discounts, country-wise availability, and a clear final verdict. It was also challenging to make the project work even when live APIs or AI services are missing, because a capstone demo still needs to be reliable during evaluation.

Next time, I would plan the data model and testing setup earlier. I added the trust pipeline, UI, accessibility improvements, and documentation near the end, but tests and deployment evidence are much easier when they are part of the project from the beginning. I would also separate demo data, live data, and AI scoring into smaller modules earlier so each part could be tested more deeply. For a production version, I would add real user accounts, saved audits, price history, rate limiting backed by a database or edge middleware, and proper monitoring from the first deployment.

One thing I learned that surprised me was how important fallback behavior is in an AI application. Before building this, I thought the AI result would be the main feature, but the app also needs to behave well when the AI is unavailable, slow, or uncertain. The heuristic fallback, strict JSON prompt, timeout handling, and clear limitations made the project feel more stable. I also learned that accessibility is not just a checklist at the end; small choices like contrast, focus states, labels, table captions, and reduced motion make the whole interface more professional and easier to use.
